# Configuration Components

Use the cards below to understand each top-level configuration component quickly: key name, whether it is required, default value, and detailed options.

<ConfigComponent
  title="Environment"
  configKey="env"
  required
  defaultValue="Dev"
  defaultOpen={false}
  summary="Selects cookie security behavior for auth tokens and is reported in engine status."
>
  ```json
  {
    "env": "Dev"
  }
  ```

  | Field | Type | Default | Description |
  |-------|------|---------|-------------|
  | `env` | string | `"Dev"` (implicit) | Controls `Secure` and `SameSite` on `bsh_access_token` and `bsh_refresh_token` cookies. |

  Allowed values (case-insensitive):

  | Value | Cookie `Secure` | Cookie `SameSite` | Typical use |
  |-------|-----------------|-------------------|-------------|
  | `Dev` | `false` | `Lax` | Local or HTTP development; same-site frontend and API |
  | `Prod` | `true` | `Lax` | HTTPS production; same-site frontend and API |
  | `CrossSiteDev` | `false` | `None` | Cross-origin development (frontend and API on different sites) |
  | `CrossSiteProd` | `true` | `None` | HTTPS production with cross-site frontend and API |

  If `env` is missing or unrecognized, the engine defaults to **`Dev`**.
</ConfigComponent>

<ConfigComponent
  title="Data Source"
  configKey="datasource"
  required
  summary="Database connection configuration for PostgreSQL, including connection, pool, and query tuning settings."
  defaultOpen={false}
>
  ```json
  {
    "datasource": {
      "host": "localhost",
      "port": 5432,
      "user": "postgres",
      "password": "secret",
      "database": "bshengine",
      "driverClassName": "org.postgresql.Driver",
      "pool": { ... },
      "query": { ... },
      "properties": { ... }
    }
  }
  }
  ```

  ### Main Fields

  | Field | Type | Default | Required | Description |
  |-------|------|---------|----------|-------------|
  | `host` | string | - | **Yes** | Database host |
  | `port` | number | `5432` | No | Database port |
  | `user` | string | - | **Yes** | Database username |
  | `password` | string | - | **Yes** | Database password |
  | `database` | string | - | **Yes** | Database name |
  | `driverClassName` | string | `"org.postgresql.Driver"` | No | JDBC driver class |

  <Callout type="info">
    The production setup uses `host`, `port`, and `database` directly.
  </Callout>

  ### Connection Pool (`pool`)

  ```json
  {
    "datasource": {
      "pool": {
        "maximumSize": 10,
        "minimumIdle": 5,
        "idleTimeout": 300000,
        "connectionTimeout": 30000,
        "maxLifetime": 1800000
      }
    }
  }
  ```

  | Field | Type | Default | Description |
  |-------|------|---------|-------------|
  | `maximumSize` | number | `10` | Maximum number of connections in the pool |
  | `minimumIdle` | number | `5` | Minimum number of idle connections to maintain |
  | `idleTimeout` | number | `300000` | Maximum idle time in milliseconds before removal (5 minutes) |
  | `connectionTimeout` | number | `30000` | Maximum wait time in milliseconds for a pool connection (30 seconds) |
  | `maxLifetime` | number | `1800000` | Maximum connection lifetime in milliseconds (30 minutes) |

  ### Query Settings (`query`)

  ```json
  {
    "datasource": {
      "query": {
        "queryTimeout": 30,
        "fetchSize": 100
      }
    }
  }
  ```

  | Field | Type | Default | Description |
  |-------|------|---------|-------------|
  | `queryTimeout` | number | `30` | Query timeout in seconds |
  | `fetchSize` | number | `100` | Number of rows fetched per database round trip |

  ### Connection Properties (`properties`)

  ```json
  {
    "datasource": {
      "properties": {
        "cachePrepStmts": "true",
        "prepStmtCacheSize": "250",
        "prepStmtCacheSqlLimit": "2048",
        "useServerPrepStmts": "true"
      }
    }
  }
  ```

  These are PostgreSQL-oriented performance options for prepared statement caching.
</ConfigComponent>

<ConfigComponent
  title="Secrets"
  configKey="secrets"
  required
  summary="Stores sensitive credentials that can be referenced elsewhere using the env: prefix."
  defaultOpen={false}
>
  For built-in secrets, see [Settings secrets](/docs/bsh-engine/settings#used-secrets).

  ```json
  {
    "secrets": {
      "mailing": {
        "provider": "gmail",
        "email": "your@email.com",
        "from": "noreply@yourapp.com",
        "fromName": "BSH Engine",
        "password": "mail-app-password"
      },
      "cloudinary": {
        "apiKey": "your-api-key",
        "apiSecret": "your-api-secret",
        "cloudName": "your-cloud-name",
        "folder": "uploads"
      }
    },
  }
  ```

  <Callout type="warning">
    Since **0.0.7**, the JWT secret is no longer read from `secrets.jwt.secret`. Move it to [`auth.config.secret`](#auth).
  </Callout>
</ConfigComponent>

<ConfigComponent
  title="Authentication"
  configKey="auth"
  required
  summary="Configures the auth provider: token signing secret, how tokens are delivered and how long sessions last."
  defaultOpen={false}
>
  ```json
  {
    "auth": {
      "provider": "self",
      "config": {
        "secret": "your-long-random-jwt-secret",
        "delivery": "Default",
        "accessTtl": 15,
        "refreshTtl": 7,
        "sessionTtl": 30
      }
    }
  }
  ```

  | Field | Type | Default | Description |
  |-------|------|---------|-------------|
  | `provider` | string | `"self"` | Auth provider. Only `self` (the engine issues its own tokens) is available. |
  | `config.secret` | string | — (**required**) | Secret used to sign tokens. Use a long random value (at least 32 characters). Without it, auth endpoints return `503 Missing Configuration`. |
  | `config.delivery` | string | `"Default"` | How tokens reach clients: `Default`, `Cookies` or `Json` (case-sensitive). See below. |
  | `config.accessTtl` | number | `15` | Access token lifetime, in **minutes**. |
  | `config.refreshTtl` | number | `7` | Refresh token lifetime, in **days**. |
  | `config.sessionTtl` | number | `30` | Maximum session lifetime, in **days**. Refreshing doesn't extend it. |

  Delivery modes:

  | Value | Auth cookies | Tokens in JSON responses | `Authorization: Bearer <jwt>` | Typical use |
  |-------|--------------|--------------------------|-------------------------------|-------------|
  | `Default` | yes | yes | accepted | Mixed clients (browser and mobile or server) |
  | `Cookies` | yes | no | not accepted | Browser-only apps; tokens never reach JavaScript |
  | `Json` | no | yes | accepted | Mobile, server or SPA clients that store tokens themselves; no CSRF |

  An unknown `delivery` value falls back to `Default`. See [Sessions](/docs/bsh-engine/auth/sessions) for how tokens and sessions work.

  <Callout type="info">
    the `provider` field is to allow us to add more auth providers in the future.
  </Callout>
</ConfigComponent>

<ConfigComponent
  title="CORS Origins"
  configKey="origins"
  required
  summary="Configure allowed origins for Cross-Origin Resource Sharing (CORS)."
  defaultOpen={false}
>
  ```json
  {
    "origins": {
      "allowed": [
        "https://yourdomain.com",
        "https://admin.yourdomain.com"
      ]
    }
  }
  ```

  | Field | Type | Required | Description |
  |-------|------|----------|-------------|
  | `allowed` | string[] | **Yes** | List of allowed origins to be used in the CORS policy.|

  <Callout type="warning">
    Patterns and wildcards like <code>https://\*</code> or <code>127.0.0.1:*</code> are <b>not</b> accepted.<br/>
    You <b>must</b> specify each allowed site exactly.<br/>
    There is <b>no default</b> value; this field is required.
  </Callout>
</ConfigComponent>

<ConfigComponent
  title="Plugin"
  configKey="plugin"
  defaultValue="coreInstallMode: Once"
  summary="Plugin system configuration."
  defaultOpen={false}
>
  ```json
  {
    "plugin": {
      "coreInstallMode": "Once"
    }
  }
  ```

  | Field | Type | Default | Options | Description |
  |-------|------|---------|---------|-------------|
  | `coreInstallMode` | string | `"Once"` | `Once`, `Always` | How core plugins are installed |

  - **`Once`**: Core plugins are installed only on first startup (recommended in production).
  - **`Always`**: Core plugins are reinstalled on every startup (useful in development).
</ConfigComponent>
