# Changelog

Track all notable changes to BSH Engine.

## 0.0.7 - To be determined (TBD)

This release focuses on fixig vulnerabilities in the authentication system and adds long-lived sessions with refresh token rotation.

**Breaking changes**
- The JWT secret moved from `secrets.jwt.secret` to [`auth.config.secret`](/docs/bsh-engine/environment/compoenents#auth). Tokens issued by earlier versions are rejected, so every user has to log in again after the upgrade.
- Access and refresh tokens no longer include `tenantId`, `roles`, `profile`, `email` or `status`. Use [Get Current User](/docs/bsh-engine/api/users/get-current-user) to read them.
- [`POST /api/auth/refresh`](/docs/bsh-engine/api/authentication/refresh-token) only refreshes the current session: it reads the refresh token from the `X-BSH-REFRESHTOKEN` header or the refresh cookie, and ignores the request body. The SDK's `auth.refreshToken()` no longer takes a payload.
- Refresh tokens rotate on every refresh. Clients must store the new refresh token (`data.refresh` or `meta.refreshToken`).
- Built-in policies were reorganized: `ROLE_BSH_ADMIN_ALLOW_ALL` is now `Bsh_Admin`, `EngineSettingsAccess` and `ACCESS_ALL_DEV` were removed, and `Bsh_UserTenantAccess` was added. See [Built-in Policies](/docs/bsh-engine/security/policies#built-in-policies).
- Auth cookies now use `Path=/api`.
- The expired session `meta.type` is now `Session expired` (was `Session Expired`). Check `meta.bshError` instead.

**Security & Sessions**
- Long sessions with short-lived tokens: access tokens last 15 minutes, refresh tokens 7 days and sessions 30 days by default, all configurable. [#450](https://github.com/bsh-devsolutions/bshengine/issues/450) [#460](https://github.com/bsh-devsolutions/bshengine/issues/460)
- [Auth sessions](/docs/bsh-engine/security/sessions) are stored on the engine (`BshAuthSessions`), with refresh token rotation and reuse detection. [#463](https://github.com/bsh-devsolutions/bshengine/issues/463) [#480](https://github.com/bsh-devsolutions/bshengine/issues/480)
- Sessions are **blocked** after 10 requests with rotated or unknown tokens (possible token theft). Using an old token once no longer closes the session. Closed sessions record a `reason`. [#489](https://github.com/bsh-devsolutions/bshengine/issues/489)
- Token expiry is computed from the issue date (`iat`) plus the configured TTL, so TTL changes apply to tokens already issued. Sessions not refreshed within `refreshTtl` expire as idle (`reason: Idle timeout`). [#462](https://github.com/bsh-devsolutions/bshengine/issues/462)
- Logout ends the session on the engine. [#461](https://github.com/bsh-devsolutions/bshengine/issues/461)
- The token type is enforced, so access and refresh tokens can't be used in place of each other. [#459](https://github.com/bsh-devsolutions/bshengine/issues/459)
- New `auth.config.delivery` option to deliver tokens through cookies, JSON responses or both. [#456](https://github.com/bsh-devsolutions/bshengine/issues/456) [#457](https://github.com/bsh-devsolutions/bshengine/issues/457)
- Silent refresh returns both `meta.accessToken` and `meta.refreshToken`.
- API keys are also accepted as `Authorization: Bearer bsh_…`. [#442](https://github.com/bsh-devsolutions/bshengine/issues/442)
- Clearer `401` errors, with a stable code in `meta.bshError`. See [Authentication errors](/docs/bsh-engine/api/authentication#authentication-errors).

**Features & Improvements**
- New [Auth Sessions API](/docs/bsh-engine/api/sessions) to list, inspect, count and revoke sessions, and the matching [SDK service](/docs/bsh-engine/sdk/services/auth-sessions). [#481](https://github.com/bsh-devsolutions/bshengine/issues/481)
- Sessions record the [device details](/docs/bsh-engine/security/sessions#device-details) at login: browser, OS, device type and the app name from the new `X-Bsh-Client` header. The client IP is not stored.
- Dashboard: new **Security → Auth Sessions** page for `BSH_ADMIN` users, and a **Sessions** section in the profile to revoke other sessions. [#482](https://github.com/bsh-devsolutions/bshengine/issues/482) [#483](https://github.com/bsh-devsolutions/bshengine/issues/483)
- SDK: `clientName` option and `withClientName()` to send `X-Bsh-Client`, `BshSessionMetaData` with the possible browser, OS and device values, and the `metadata` field on `BshAuthSession`.
- SDK: `isExpired()` helper and `BshErrorCode` type.
- `GET /api/utils/version` no longer requires authentication.
- More flexible [date parsing](/docs/bsh-engine/modeling/types#date-values): ISO variants, short offsets, epoch seconds and milliseconds. Values without an offset are treated as UTC.

## 0.0.6 - 03 Oct 2026

**Security & Access Controls**
- Fixed vulnerabilities in dependencies.
- Fixed vulnerability: Broken API authorization; anonymous access to privileged endpoints. [#419](https://github.com/bsh-devsolutions/bshengine/issues/419)
- Restricted access to X-Tenant-Id header to only authenticated users. Normal users can only access their assigned tenant. [#434](https://github.com/bsh-devsolutions/bshengine/issues/434)
- Denied access to managed entities (users, tenants, etc.) from generic endpoints `/api/entitites/:entity`. [#420](https://github.com/bsh-devsolutions/bshengine/issues/420)
- Required `BSH_ADMIN` to activate accounts; non-admins cannot set status to ACTIVATED via user update or the generic entity API. [#420](https://github.com/bsh-devsolutions/bshengine/issues/420)
- Restricted assigning `BSH_ADMIN` role to only `BSH_ADMIN` users. [#420](https://github.com/bsh-devsolutions/bshengine/issues/420)
- Improved CORS policy: **`origins.allowed`** accepts only exact origins; wildcard patterns (for example `https://*`, `127.0.0.1:*`) supported before **0.0.6** are no longer valid. [#421](https://github.com/bsh-devsolutions/bshengine/issues/421)
- Enabled CSRF protection for cookie sessions. [#421](https://github.com/bsh-devsolutions/bshengine/issues/421)
- Improved JSON configuration to allow setting for CSRF and auth cookies. [#430](https://github.com/bsh-devsolutions/bshengine/issues/430)
- Fixed access token refresh issue.
- API keys authenticate with `Authorization: <api-key>`. The legacy `X-BSH-APIKEY` header is deprecated.
- Header JWT clients: optional `X-BSH-REFRESHTOKEN`, silent refresh, and `meta.accessToken` on responses. [#443](https://github.com/bsh-devsolutions/bshengine/issues/443)

**Features & Improvements**
- Upgraded Trigger to support lookups. [#375](https://github.com/bsh-devsolutions/bshengine/issues/375)
- Outgoing emails support a **From** display name via `fromName` on send, in [mail provider config](/docs/bsh-engine/mailing/configurations#sender-display-name), or `secrets.mailing.fromName`. [#416](https://github.com/bsh-devsolutions/bshengine/issues/416)

**Testing**
- Added tests to the engine for more robust development and deployment.

## 0.0.4 - 02 Feb 2026

**Highlights**
- Centralized engine configuration using a single JSON object passed via the [`BSH_CONFIG`](/docs/bsh-engine/environment) environment variable.
- [Secret management system](/docs/bsh-engine/settings#secrets) for secure storage of sensitive data.
- Cookie-based authentication with secure token storage.
- New system health checks via `/api/status` and `/status` view to verify setup integrity.
- Move docker repository from `bshg/engine` to [`bshsolutions/engine`](https://hub.docker.com/r/bshsolutions/engine)

**Authentication & Security**
- Cookie-based authentication with secure token storage.
- Embedded password verification.
- Activation and password reset codes now expire after **10 minutes**.
- Default authentication email templates redesigned for clarity.
- Security improvements across both API and Dashboard.

**Users & Access Management**
- User IDs now use **UUID** format for improved uniqueness and security.
- Admin user invitation system with role assignment via [`/api/users/invite`](/docs/bsh-engine/api/users/invite-user).
- Password auto-generation option using [`?generatePassword=true`](/docs/bsh-engine/api/users/init-user#generate-password) on `/api/users/init`.
- Activation email resend endpoint: [`/api/auth/resend-activation-email`](/docs/bsh-engine/api/authentication/resend-activation-email).

**Email & Notifications**
- API key [notification emails](/docs/bsh-engine/mailing/email-templates#authentication-templates) sent on **create**, **revoke**, and **delete** actions.
- Support for [`{{host}}`](/docs/bsh-engine/mailing/email-templates#host-variable) as an internal variable in email templates.

**Plugins & Extensibility**
- Install plugins as ZIP files via [`/api/plugins/install/zip`](/docs/bsh-engine/api/plugins/install-zip).
- Reinstall the core plugin via [`/api/plugins/install/core`](/docs/bsh-engine/api/plugins/install-core).
- Plugin installation history tracking.
- Dynamic JavaScript (ES6) execution in triggers for advanced logic.

**API & System**
- New `/api/status` endpoint for system and setup health checks.
- Improved error handling with clearer and more descriptive error messages.

**Dashboard & UI**
- Improved dashboard performance with smaller bundles and faster load times.
- UI/UX enhancements for a smoother user experience.

**Developer Experience**
- React starter template for faster engine integration. See [Templates Docs](/docs/bsh-engine/templates).
- Add [`docker`](/docs/bsh-engine/cli/docker) command to CLI to generate compose files.
