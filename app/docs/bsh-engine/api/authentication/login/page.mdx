# Login

Authenticate a user with email and password.

```bash
POST /api/auth/login
```

Each successful login opens a new [auth session](/docs/bsh-engine/auth/sessions) on the engine and returns an access token and a refresh token for it.

<Callout type='info'>
  How the tokens are returned depends on [`auth.config.delivery`](/docs/bsh-engine/environment/compoenents#auth):
  - `Default`: tokens in the response body **and** in the `bsh_access_token` / `bsh_refresh_token` cookies.
  - `Cookies`: cookies only. The response `data` is empty.
  - `Json`: response body only, no cookies.
</Callout>

<Callout type='important'>
  Password requirements:
  - Length: 6-12 characters.
  - At least one uppercase letter.
  - At least one lowercase letter.
  - At least one number.
</Callout>

<Callout type="error">
  The engine signs tokens with `auth.config.secret`.
  Before starting the instance, set it in your configuration as described in [Authentication configuration](/docs/bsh-engine/environment/compoenents#auth).
</Callout>

## Request Headers

| Header | Required | Description |
|--------|----------|-------------|
| `X-Bsh-Client` | No | Identifies the application initiating login. Stored in the session's [device details](/docs/bsh-engine/auth/sessions#device-details). The SDK sends it when [`clientName`](/docs/bsh-engine/sdk/configuration) is set. |
| `User-Agent` | No | Identifies the browser, operating system, and device. [device details](/docs/bsh-engine/auth/sessions#device-details). |

## Request Body

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

## Response

```json
{
  "data": [
    {
      "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
    }
  ],
  "message": "Login successful",
  "meta": { "type": "Login" }
  ...
}
```

| Field | Description |
|-------|-------------|
| `access` | Access token. Short-lived (`auth.config.accessTtl`, 15 minutes by default). |
| `refresh` | Refresh token. Used to get new tokens for the same session (`auth.config.refreshTtl`, 7 days by default). |

<Callout type='warning'>
  The tokens only carry session identifiers (`sub`, `sid`, `jti`), not the user's roles, tenant or profile. Use [Get Current User](/docs/bsh-engine/api/users/get-current-user) to read the user.
</Callout>

## User Status

| Status | Description | can login |
|--------|-------------|-------------|
| `ACTIVATED` | User account is activated. | Yes |
| `REQUIRED_ACTIVATION` | User account is not activated. | No |
| `REQUIRED_RESET_PASSWORD` | User need to reset the password. | No |
| `DISABLED` | User account is disabled. | No |
| `LOCKED` | User account is locked. | No |
